## 2. 問題定義（Problem Statement）

台灣已進入超高齡社會，實務上有兩大痛點：

1. **資源破碎、查找門檻高**：長照、醫療、交通、補助等資源，分散在衛福部與各縣市政府數十個網站，且用語專業。長者與家屬「知道有資源，卻不知道去哪找、怎麼申請」。
2. **高齡孤獨與社會孤立**：獨居比例攀升，長輩缺乏連結與陪伴，衍生孤獨死的社會隱憂。單純的資源清單無法解決「孤單無依」。

**設計假設**：把政府開放資料整理成「在地化、口語化、好操作」的入口，並加入互動與陪伴功能，能同時降低查找門檻與增進社會連結。

## 4. 開發歷程：從 Prototype 到產品

### 4.1 階段 0 — 概念發想與原型（Concept & Prototype）
- **概念起源（2024）**：源自台大團隊與中華民國老人福利推動聯盟（老盟）合作發想，聚焦「高齡孤獨」與「資源查找困難」兩大課題。
- **獨立開發**：其後由江易庭（Morris Chiang）將概念獨立實作為開源服務網站與 LINE 官方帳號。
- 以「一頁式資源清單」驗證核心價值：長輩打一個字 → 找到能打的電話。
- 產出：手機優先的視覺原型（Hero 搜尋框 + 六大功能格 + 分類瀏覽）。

### 4.2 階段 1 — 資料骨架（Data Foundation）
- 設計 `regions／categories／subcategories／resources` 四張核心表。
- 建立八大分類、67 個細標籤的分類體系（見文件 04）。
- 匯入第一批政府開放資料（社區關懷據點、老人福利機構）。

### 4.3 階段 2 — 在地化與帳號（Localization & Auth）
- 地區樹（縣市 → 行政區，391 筆），依 cookie／個人資料判斷所在地。
- 導入 Supabase Auth（LINE／Google／手機驗證碼三種登入）、`profiles`、`account_links`。

### 4.4 階段 3 — 互動與陪伴（Engagement）
- 互助問答（questions／answers／answer_votes）。
- 活動圖卡（activity_cards）、溝通錦囊（communication_scripts）、今日新知（daily_news）。
- 收藏、按讚、分享給家人、回報資料有誤。

### 4.5 階段 4 — LINE 智慧客服（Conversational）
- 串接 LINE Messaging API（Webhook、Flex Message、Rich Menu、Quick Reply、Postback）。
- 情境式 FAQ 自動回覆（含安全分流）＋在地資源查詢。

### 4.6 階段 5 — 資料規模化與搜尋精準化（Scale & Precision）
- 資源擴充至 18,020 筆（全縣市、多資源類型）。
- 建立共用搜尋核心：地區解析 → 口語對照 → 情境 FAQ → 相關度排序（見文件 03）。

### 4.7 階段 6 — 上線與擴散（Launch & Distribution）
- 佈署至 Vercel（正式站）。
- 準備上架「政府資料開放平台 — 資料活化應用」，對外擴散服務。

## 5. 功能需求（Functional Requirements）

### 5.1 核心：資源查找
- **FR-1 智慧搜尋**：使用者以口語輸入需求（如「爸爸不舒服想去醫院」），系統對應到正確服務並依相關度排序。
- **FR-2 在地化**：自動判斷縣市／行政區，優先顯示在地資源；支援跨區、區域群組（南部、離島…）與同名地區消歧（大安、信義…）。
- **FR-3 分類瀏覽**：八大分類 × 67 細標籤，可多標籤篩選。
- **FR-4 資源詳情**：名稱、摘要、電話（可一鍵撥打）、地址、標籤、資料來源，收藏／分享／回報。

### 5.2 互動與陪伴
- **FR-5 互助問答**：發問、回答、票選、標記最佳解答。
- **FR-6 活動圖卡**：手作、運動、園藝、懷舊等步驟式內容。
- **FR-7 溝通錦囊**：跨代溝通「照著說」句子（正例／反例）。
- **FR-8 今日新知**：高齡照顧新知與防詐提醒。

### 5.3 LINE 智慧客服
- **FR-9 加好友即用**：免註冊、免下載，打字或點選單即可查詢。
- **FR-10 情境式回覆**：情境／安全分流（急症→119、詐騙→165、情緒→1925）。
- **FR-11 地區記憶**：記住使用者所在地，並支援對話中換地區確認。

### 5.4 帳號與後台
- **FR-12 多元登入**：LINE／Google／手機驗證碼。
- **FR-13 管理後台**：資源審核、分類分佈、用戶管理、聊天紀錄、內容回報處理。

## 7. 使用者旅程（User Journeys）

**旅程 A｜家屬幫長輩找長照（網頁）**
選擇／自動判斷地區 → 首頁輸入「長照申請」→ 相關度排序結果（全國→縣市→區）→ 進資源詳情 → 一鍵撥打 1966／在地據點 → 收藏、分享給家人。

**旅程 B｜長輩用 LINE 問（對話）**
加 LINE 好友 → 首次設定地區 → 打「中壢 量血壓」→（若與設定地區不同）跳換地區確認卡 → 顯示在地資源 Flex 卡 → 點「撥打電話」。

**旅程 C｜情緒／急迫情境（安全分流）**
打「爸爸不舒服想去醫院」→ 先給安全分流訊息（119／接送／找院所）→ 引導下一步。

## 10. 功能規格細節與驗收準則（Detailed Specs & Acceptance）

### 10.1 智慧搜尋（FR-1 / FR-2）
- **輸入**：自然語句，含或不含地區、含或不含標點。
- **處理**：地區解析（詞序無關）→ 口語對照 → 情境 FAQ → 相關度排序。
- **驗收準則**：
  1. 「台北松山 長照」→ 解析為 台北市+松山區，關鍵字「長照」。
  2. 「大安區送餐」→ 跳同名消歧（台北/台中大安區）。
  3. 「南部有大型醫療機構嗎」→ 展開為南部六縣市，全國優先排序。
  4. 「民生社區送餐」→ 判定未知地名、以預設地區推薦並提示。
  5. 「救護車」「送便當」等口語 → 對應到正確細標籤。
  6. 結果依相關度由高到低，最相關者於首屏。

### 10.2 在地化與地區衝突
- **規則**：僅在「偵測到地區且與目前選擇不同」時提示；相同或未設定則直接搜。
- **驗收**：目前設定「桃園龍潭」，打「龍潭 長照」不打擾直接搜；打「台南 長照」跳確認卡。

### 10.3 安全分流（FR-10）
- **驗收**：胸痛／昏倒／中風徵兆 → 立即回 119 相關訊息；「孫子打來要錢」→ 165；情緒低落 → 1925；且**不被地區流程蓋掉**。

### 10.4 收藏 / 說讚（跨裝置）
- **驗收**：登入後於手機收藏，電腦重新整理後可見；未登入點收藏導向登入。

## 11. 系統邊界與整合（System Boundaries）

| 外部系統 | 整合方式 | 備註 |
|---|---|---|
| Supabase | Auth + PostgreSQL + RLS | 資料與登入 |
| LINE Messaging API | Webhook + 主動回覆 | 驗簽、Flex、Rich Menu |
| Anthropic Claude | REST（意圖／客服回答） | 失敗時回退關鍵字法／罐頭訊息 |
| 政府開放資料 | 批次匯入（非即時） | data.gov.tw、各縣市 |
| Vercel | 佈署與 CDN | 正式站 |

## 12. 開發流程與版本控管（Dev Process）

- **分支策略**：主線 `main`；功能於分支開發、審查後合併。
- **資料庫遷移**：所有 schema 變更寫成 `supabase/migrations/00XX_*.sql`，序號遞增、可重播（`if not exists`）。
- **佈署**：`npx vercel --prod` 佈署至正式站；正式網域自動別名。
- **設定管理**：機敏設定以環境變數管理（見技術文件 §6），不入庫。
- **測試策略（規劃）**：搜尋核心以「查詢→預期分類/地區」測試清單守護，避免改 A 壞 B。
